# CORY DAVIS // PROOF LEDGER

```text
ARTIFACT → HASH
VERSION  → GIT COMMIT
PUBLIC RECORD → DOI / DRIVE ID / REPOSITORY TIMESTAMP
CLAIM → TEST / CONTROL / NULL / REPLICATION
```

This ledger makes the portfolio's proof model explicit. Different evidence answers different questions.

## Proof layers

| Layer | Establishes | Does not establish |
|---|---|---|
| SHA-256 | Exact byte identity/integrity of a file | authorship, correctness, scientific truth |
| Git commit history | Public version/timestamp lineage for repository content | authorship of every upstream/third-party byte |
| Drive file ID / timestamp | Stable downloadable source-file record | scientific validity or independent verification |
| DOI / deposited record | Stable citable publication/deposit record | peer review or truth of every claim |
| Runtime logs / tests | A mechanism executed under the captured conditions | broad generalization |
| Controlled benchmark | Performance on the declared model/data/seeds/metric | universal superiority |
| Independent replication | Another implementation/test can reproduce a result | correctness outside the replicated scope |
| NULL result | Declared success criterion was not met | that every related hypothesis is impossible |

## Benchmark anchors and bounded conclusions

### Dynamic-state attention

The canonical manual records a frozen-corpus seven-rung comparison in which dyn12 produced the strongest mean validation loss among the tested state-mechanism rungs and improved over the no-state baseline across the three reported seeds.

**Bounded conclusion:** a compact dynamic state modulating attention helped the documented small character-level architecture on that benchmark and did so cheaply in parameters.

**Not claimed:** that 12 dimensions are universally optimal or that dyn12 beats every static/larger model on absolute loss.

### Quantum provenance

Specific archived measurement paths can provide auditable measurement-derived provenance and deterministic downstream seed/weight derivation.

**Bounded conclusion:** provenance/nondeterminism source can be documented.

**NULL / unsupported:** matched public experiments do not currently establish a general ML accuracy advantage from quantum randomness.

### Paired sensory/internal state

The documented 2026-07-30 paired-state benchmark retained the aligned condition as **NULL versus plain attention** even though it beat some destroyed-pairing conditioned controls.

**Why this matters:** the portfolio publishes the failure criterion rather than changing it after the result.

### HEHS

The v2 guide explicitly replaces fixed power promises with source characterization, stored-joule measurement, leakage controls, repeatability, tuned-vs-control comparisons, and load energy budgets.

**Current evidence status:** engineering prototype specification / measurement plan until a particular physical build's raw measurements are published.

### HEARTLIGHT

Software tests and CI can establish reference implementation behavior.

**Not claimed:** medical efficacy, diagnosis accuracy, automated behavioral truth, legal compliance certification, or clinical validation.

### COSMOS Media

Tests can establish generation/integration behavior, deterministic receipts, timeline planning, and cross-language execution.

**Not claimed:** physical multiverse access, consciousness, or quantum performance advantage.

## Reproduce a source hash

macOS/Linux:

```bash
sha256sum FILE
# or
shasum -a 256 FILE
```

PowerShell:

```powershell
Get-FileHash .\FILE -Algorithm SHA256
```

Compare a 00–24 Word document with `WORD_LIBRARY_2026-08-12.sha256`, a dated Markdown source with `archive/2026-08-12/DOCUMENT_ARCHIVE_2026-08-12.sha256`, or a flagship publication binary with `ARTIFACTS.sha256`.

## Reproduce a repository version

Use a Git commit SHA rather than only a branch name when citing a frozen version:

```bash
git show COMMIT_SHA
```

## Evaluate a scientific claim

```text
1. identify exact artifact/model
2. identify exact code version
3. identify dataset/corpus fingerprint
4. identify seeds/configuration
5. inspect mechanism preflight
6. inspect baseline and controls
7. inspect metric and success criterion
8. inspect per-run/per-seed result
9. preserve nulls/retractions
10. replicate before broadening the claim
```
