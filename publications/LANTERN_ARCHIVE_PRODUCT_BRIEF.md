## What it is

The Lantern Archive is a family-controlled, local-first toolkit for preserving relationship records across time: stories, phrases, photographs, video, audio, values, lessons, favorite things, and an optional heartbeat-derived rhythm signature.

A Lantern is a **new computational memorial assembled from supplied records and family teaching**. It is not represented as the biological person, a recovered soul, or proof that consciousness survives death.

## Engineering surface

The public repository contains or documents:

- a family-facing HEARTLIGHT Home interface;
- drag-and-drop evidence import;
- local memorial vaults and ZIP backup;
- text/media evidence manifests with SHA-256 provenance;
- append-only family teaching;
- deterministic grounded memorial-profile construction;
- PCM-WAV heartbeat/pulse-style rhythm analysis;
- a language-neutral HIP event protocol;
- optional Azure Blob Storage and IBM Cloud Object Storage adapters;
- a FastAPI reference/enterprise service;
- Docker and Kubernetes deployment baselines;
- SDK source trees for Python, Rust, C++, TypeScript, Swift, Kotlin, Go, .NET/C#, and Java;
- tests and GitHub Actions CI;
- family, teacher/facilitator, science, ethics/safety, architecture, protocol, SDK, and enterprise documentation.

## Heartbeat role

The heartbeat is treated as a **signal artifact**, not a personality container. The software can extract beat times, interval structure, BPM summaries, checksums, and a reproducible rhythm digest. Downstream systems can use that signature for timing, haptics, animation, music, scheduler phase, or state-machine transitions.

Semantic/personality-like behavior comes from the evidence corpus, provenance, and family teaching layered around that signal.

## Cloud boundary

Cloud sync is optional. The local vault is the reference source of truth. Azure and IBM integrations are storage/mirroring adapters, not claims that cloud services recreate a deceased person.

## Safety / ethics boundary

The repository explicitly requires:

1. no resurrection claims;
2. no deceptive impersonation;
3. consent and family governance over supplied records;
4. provenance for evidence and derived artifacts;
5. deletion, shutdown, and silence controls;
6. no grief-engagement optimization or guilt-based retention.
